# 农产品小程序前后端打通计划

## 目标

在现有原生微信小程序 `RuoYi-wx-app` 上完成真实商城接口接入，让用户能够浏览农产品、选择 SKU、维护本地购物车、微信登录、管理地址、领取优惠券、提交订单、微信支付并查看订单状态。

本计划依赖《商城运营后台落地计划》的 12 张表和事务规则，前台、后台共用商品、库存、会员、订单和优惠券事实源，不另建一套“小程序商城”模型。

登录、购物车、下单、支付、取消、发货和库存状态的详细时序见[农产品小程序业务流程图](./2026-07-27-农产品小程序业务流程图.md)。

首期面向当前已有的黄精切片、茶、粉、蜂蜜、坚果、菌菇等常温或干制农产品。鲜果、冷链、称重计价、预售采摘、团购、分销、直播、在线售后和多商户不在本期范围。

## 最小设计决定

1. **不重写小程序**：继续使用原生页面和现有样式，只替换数据源并补齐关键交互。
2. **不增加购物车表**：游客和会员购物车均保存为本地 `{skuId, quantity, selected}`；每次进入购物车和结算页调用服务端预览接口刷新商品状态、价格和库存。
3. **不增加运费模板表**：首期使用 `sys_config` 保存统一运费、包邮门槛、发货说明和不可配送地区；出现冷链或按地区计费后再建模板。
4. **金额只传分**：接口中的价格和金额使用整数分，前端统一格式化展示，不用浮点数参与结算。
5. **服务端是最终裁决者**：前端不得提交商品名称、单价、优惠金额、运费、订单状态或会员 ID；创建订单时由后端重新计算。
6. **公开浏览、按需登录**：首页、分类、搜索、详情和购物车预览允许游客访问；结算、领券、地址和订单操作时才触发微信登录。
7. **前后台身份隔离**：`mall_member` 会话不能复用 `sys_user` 的管理员身份，管理员 token 也不能访问任意会员订单。
8. **只增加一个安全依赖**：支付阶段采用微信支付 API v3 官方 Java SDK完成签名、验签和回调解密，不手写支付密码学；其余能力使用当前 Spring、Redis 和 RuoYi 组件。

## 数据模型补充

不增加业务表，只在尚未执行的商城建表脚本中补充三个字段：

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `mall_product` | `product_params_json` | 保存可展示的产地、净含量、加工方式、配料、储存条件、保质期等键值参数；不用于跨商品筛选。 |
| `mall_order` | `client_request_no` | 小程序生成并在提交重试时保持不变；唯一 `(member_id, client_request_no)`，保证重复点击或网络重试只产生一个订单。 |
| `mall_order` | `pay_prepay_id` | 首期一单一次微信支付，缓存该订单的预支付标识，支付取消后可在订单有效期内重新拉起。 |

配置复用 `sys_config`，首期只需要 `mall.freight.amount`、`mall.freight.freeThreshold`、`mall.order.expireMinutes`、`mall.delivery.notice` 和 `mall.delivery.unsupportedRegionCodes`。管理端商品表单同步支持维护 `product_params_json`。

执行任何相关 DDL/DML 前，必须先生成并检查 `sql/update/` 下的 SQL 文件。若商城业务表脚本尚未执行，三个字段直接纳入 `2026-07-24-01-新增商城业务表.sql`；商城配置使用单独的 `2026-07-27-新增小程序商城配置.sql`。禁止先执行内联 SQL 再补文件。

## API 契约

接口统一前缀为 `/app/shop`，与管理端 `/shop` 区分。单对象和写操作沿用 `AjaxResult`：`{ code, msg, data }`；分页沿用 `TableDataInfo`：`{ code, msg, rows, total }`。HTTP 2xx 但 `code != 200` 仍视为失败。

### 公开接口

| 方法 | 路径 | 返回和规则 |
| --- | --- | --- |
| `POST` | `/app/shop/auth/login` | 接收一次性 `code`，服务端调用 `code2Session`，按 `(app_id, open_id)` 创建或更新会员并返回会员 token；不接收客户端 OpenID。 |
| `GET` | `/app/shop/home` | 一次返回有效 Banner、一级分类、最新上架和真实热销商品；季节内容由 Banner 承载，不增加推荐字段。 |
| `GET` | `/app/shop/categories` | 返回启用的两级分类树，不返回后台审计字段。 |
| `GET` | `/app/shop/products` | 支持 `categoryId`、`keyword`、`pageNum`、`pageSize`；只返回上架且至少有一个启用 SKU 的商品，库存为零时明确标记售罄。 |
| `GET` | `/app/shop/products/{productId}` | 返回图片、详情、农产品参数、可售 SKU、实时库存状态和少量同类推荐。 |
| `POST` | `/app/shop/cart/preview` | 接收 SKU 与数量，返回当前商品快照、可售状态、库存校验和商品金额；不创建购物车记录。 |
| `GET` | `/app/shop/coupons` | 返回当前可领取的全店满减券；已登录时同时标记是否已领取。 |

### 会员接口

| 方法 | 路径 | 返回和规则 |
| --- | --- | --- |
| `POST` | `/app/shop/auth/logout` | 删除当前会员 Redis 会话。 |
| `GET` | `/app/shop/me` | 返回会员基础资料、各订单状态数量、可用优惠券数量。 |
| `GET/POST` | `/app/shop/member/addresses` | 查询和新增当前会员地址。 |
| `PUT/DELETE` | `/app/shop/member/addresses/{addressId}` | 修改或逻辑删除本人地址，必须校验归属。 |
| `PUT` | `/app/shop/member/addresses/{addressId}/default` | 事务内取消旧默认地址并设置新默认地址。 |
| `GET` | `/app/shop/member/coupons` | 按 `AVAILABLE/USED/EXPIRED` 查询本人优惠券。 |
| `POST` | `/app/shop/coupons/{couponId}/claim` | 条件更新发放量并创建会员券，校验领取窗口、总量和每人限领。 |
| `POST` | `/app/shop/orders/preview` | 接收地址、SKU 数量和可选会员券，返回商品、运费、优惠、应付金额及不可下单原因，不写订单。 |
| `POST` | `/app/shop/orders` | 接收 `clientRequestNo`、地址、SKU 数量、会员券和留言；按后台计划的事务规则创建订单。 |
| `GET` | `/app/shop/orders` | 支持状态和分页，只查询当前会员订单。 |
| `GET` | `/app/shop/orders/{orderNo}` | 返回当前会员的订单、明细、地址快照、金额、物流和可执行动作。 |
| `POST` | `/app/shop/orders/{orderNo}/cancel` | 仅本人待支付订单可取消，重复取消返回最终状态。 |
| `POST` | `/app/shop/orders/{orderNo}/confirm-receipt` | 仅本人已发货订单可确认收货。 |
| `POST` | `/app/shop/orders/{orderNo}/payment` | 校验本人待支付订单，创建或复用 `prepay_id`，返回 `wx.requestPayment` 所需参数。 |

### 微信支付通知

`POST /app/shop/payment/wechat/notify` 对网络匿名开放，但必须由官方 SDK 使用原始请求体和微信支付请求头完成验签、解密，并核对商户号、AppID、订单号和支付金额。验证后在事务中幂等更新订单、实扣锁定库存、核销优惠券并写流水；客户端支付成功回调不能直接改变订单状态。

订单超时任务若已经创建微信预支付单，应先调用微信关单；遇到“已支付”则查询并按支付成功处理，关单成功后才能取消本地订单，避免支付回调和超时释放库存竞争。

## 会员认证

1. 小程序在需要会员能力时调用 `wx.login`，把一次性 code 发送到后端；`AppSecret` 只存在于后端环境配置。
2. 后端使用现有 HTTP 能力调用微信 `code2Session`，不为登录引入综合型微信 SDK。
3. 后端签发不可预测的随机 token，在 Redis 中保存 `memberId`、`appId`、状态和过期时间；请求仍使用 `Authorization: Bearer <token>`。
4. 增加只处理 `/app/shop/**` 的会员认证过滤器和会员 principal；公开接口使用 `@Anonymous`，会员接口显式要求会员 principal。
5. 会员被禁用、token 过期或 Redis 会话不存在时返回 401。小程序清理本地会话并重新 `wx.login`；普通 POST 不自动重放，订单提交依靠 `clientRequestNo` 安全重试。
6. 登录、领券和支付接口复用 RuoYi `@RateLimiter`；`@RepeatSubmit` 只作为短时间点击保护，不能替代数据库幂等和事务条件。

| 地址 | 新增 `pages/address/edit/index`，完成新增、编辑、删除、默认地址和省市区选择；结算页选择地址后原路返回刷新。 |
| 优惠券 | 新增 `pages/coupon/list/index`，显示可领取和我的券；不可用原因直接展示，不做复杂活动会场。 |

| 个人中心 | 调用 `/me` 展示真实订单角标和优惠券数量；删除钱包、银行卡、分销、聊天和未实现售后入口；客服优先使用微信原生客服能力。 |

当前商品属于普通食品或食用农产品时，只展示后台有依据的产地、成分、加工和质量信息，不使用疾病预防、治疗或无法证明的保健功效文案。不得统一硬编码“7 天无理由”；服务说明按实际商品和现行规则配置，质量问题仍保留客服处理渠道。

## 前端数据流

小程序只增加必要的共享文件：

```text
RuoYi-wx-app/
├── api/shop.js          # 所有商城接口，避免每个页面手写 wx.request
├── utils/config.js      # develop / trial / release API 地址
├── utils/request.js     # RuoYi 响应、token、401、错误和 loading 计数
└── utils/cart.js        # 本地购物车读写、合并、删除和数量统计
```

页面继续用自身 `data` 和 `setData` 管理状态，不增加全局状态库。`utils/request.js` 负责以下统一行为：

1. 根据 `wx.getAccountInfoSync().miniProgram.envVersion` 选择环境地址，禁止把 AppSecret、商户私钥或 API v3 密钥放入小程序。
2. 统一解析 `AjaxResult` 和 `TableDataInfo`，把业务错误转换为包含 `code` 和 `msg` 的错误对象。
3. 多个并发请求共用 loading 计数，最后一个请求结束后才隐藏；页面可关闭全局 loading 并显示局部骨架。
4. 401 只触发一次会话清理和登录引导；网络错误、超时、业务失败使用不同提示，不把后端堆栈展示给用户。
5. 页面卸载或筛选条件变化后忽略旧响应，防止慢请求覆盖新数据。
6. 所有金额由 `priceCent` 等分值统一格式化成两位元字符串，WXML 不直接做乘法结算。

## 核心流程

### 加购和结算

```text
商品详情选择 SKU
    -> 本地购物车合并数量
    -> 购物车预览刷新价格/库存
    -> 选择结算项
    -> 按需微信登录
    -> 订单预结算
    -> 用户确认地址/优惠券/运费
    -> 幂等创建订单
```

预结算结果只是展示快照。正式创建订单仍重新读取数据库并完成库存锁定、优惠券锁定和金额计算。创建成功后只删除本次已下单的本地购物车项；请求失败保留购物车。

### 支付

```text
创建待支付订单
    -> 后端微信支付预下单
    -> 返回 requestPayment 参数
    -> 小程序 wx.requestPayment
    -> 微信异步通知后端
    -> 后端验签/验金额并提交支付事务
    -> 小程序重新查询订单状态
```

小程序无论收到 `success`、`fail` 还是用户取消，都重新查询订单详情；只有服务端订单为 `PENDING_SHIPMENT` 才展示支付成功。零元订单不调用微信支付，由订单 Service 在创建事务中直接完成支付状态迁移。

## 后端实现边界

1. 继续放在现有 `ruoyi-system`、`ruoyi-framework` 和 `ruoyi-admin`，不新增 Maven 模块。
2. 小程序 Controller 返回专用 DTO，不直接序列化数据库实体，不暴露成本、锁定库存、删除标记、管理员备注或其他会员信息。
3. 公开商品查询必须同时校验分类启用、商品上架、SKU 启用和逻辑删除；详情不存在或已下架统一返回不可购买。
4. 所有会员资源按 token 中的 `memberId` 查询，路径或请求体不接受 `memberId`。
5. 地址、关键词、留言、分页、SKU 数量和 JSON 参数在 Controller/DTO 边界校验长度、范围和格式；富文本在后台保存时做白名单清理。
6. 支付采用微信支付官方 Java SDK的单例配置和 `JsapiServiceExtension`，复用其签名、验签和通知解析；实施时确认与 Java 8 兼容的当前稳定版本，不复制网络示例自行实现签名。
7. 日志只记录订单号、会员 ID、支付结果码和追踪信息，不记录 AppSecret、session key、完整 token、私钥、API v3 密钥、完整地址或通知明文。

## 实施顺序

### 1. 前置配置和契约

准备真实小程序 AppID、后端 AppSecret、HTTPS API 域名和合法 request/download 域名。支付联调前再准备商户号、商户证书序列号、私钥、API v3 密钥、微信支付公钥或平台证书以及公网通知地址；秘密通过环境变量或外部配置注入。

先把三个补充字段和 `sys_config` 初始化写入 `sql/update/` SQL 文件并检查，再执行数据库变更。随后固定 DTO 字段、错误码、订单状态和前后端接口清单。

### 2. 公开浏览链路

先实现首页、分类、商品分页、搜索、详情和购物车预览接口；小程序完成环境配置、请求封装、`api/shop.js`、真实图片和金额格式化。此阶段游客可完整浏览和维护本地购物车。

### 3. 会员链路

实现微信 code 登录、Redis 会员会话、会员认证过滤器、个人中心、地址 CRUD、优惠券领取与查询。删除账号密码演示登录和无业务入口。

### 4. 订单链路

实现预结算、幂等创建、列表、详情、取消和确认收货；补齐小程序确认订单、订单列表、订单详情和地址编辑交互。先用真实待支付状态验收库存与优惠券事务，不伪造支付成功。

## 验证与验收

1. 首页、分类、搜索和详情的数据与运营后台上架内容一致；下架、禁用或售罄商品不可下单。
2. 游客能加购，登录后购物车不丢失；价格变化、库存不足和商品失效在购物车及确认页得到明确提示。
3. 相同 `clientRequestNo` 并发或重试只产生一个订单、一次库存锁定和一组流水；不同请求正常生成不同订单。
4. 前端篡改单价、优惠、运费、会员 ID、订单状态或其他会员订单号均无效或被拒绝。
5. 地址和订单只能由所属会员访问；管理员 token、过期 token 和伪造 token 不能越权访问会员接口。
6. 支付回调重复、乱序、金额不符、签名错误和支付/取消竞争均不产生重复实扣、负库存或重复核销。
7. 用户取消收银台后订单仍为待支付并可重试；异步通知延迟时页面轮询服务端，不依据客户端回调误报成功。
8. 所有列表覆盖首屏加载、下拉刷新、触底分页、空数据、失败重试；提交按钮有禁用态且文字不溢出。
9. 真机在 develop/trial/release 对应域名下完成登录、图片加载、下单和支付；小程序包中搜索不到任何服务端秘密。
10. 后端事务测试、认证越权测试、支付通知测试、Maven 构建和微信开发者工具关键路径回归全部通过，运行时不再读取 Mock 数据。

## 外部前置条件

真实支付不能仅靠代码完成，以下任一项缺失时可以完成到“真实待支付订单”，但不能宣称支付打通：

1. 已认证且类目符合农产品/食品销售的小程序 AppID。
2. 已关联可用的微信支付商户号。
3. 后端可访问的 HTTPS 域名、微信后台合法域名和公网支付通知地址。
4. 安全保存的 AppSecret、商户私钥、证书序列号、API v3 密钥及微信支付公钥或平台证书。

实施时以[微信支付小程序支付开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791911)、[JSAPI/小程序下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791856)、[支付成功回调通知](https://pay.wechatpay.cn/doc/v3/merchant/4012791861)和[微信支付 API v3 官方 Java SDK](https://github.com/wechatpay-apiv3/wechatpay-java)为准。农产品页面和结算提示还需按实际商品核对[网络购买商品七日无理由退货暂行办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_26ca8fe29e184edd899fa0a7a060d935.html)及上线时适用的食品销售规则。
